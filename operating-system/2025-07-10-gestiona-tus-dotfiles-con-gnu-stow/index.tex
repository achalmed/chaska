\abstract{This tutorial provides a step-by-step guide to managing
dotfiles using GNU Stow, a tool that leverages symbolic links to
centralize and synchronize configuration files across Unix-like systems
(Linux, macOS, WSL). It explains the importance of dotfiles, such as
.bashrc and .gitconfig, in customizing user environments and highlights
the inefficiencies of manual management. The guide details installing
GNU Stow, creating a dotfiles repository, linking configurations, and
automating the process with a bash script. Advanced tips include
handling conflicts, platform-specific setups, and alternatives like
Chezmoi and YADM. This resource is designed for developers seeking
efficient, portable configuration management. }

\section[Introduction]{Gestiona dotfiles fácilmente con GNU Stow}

\setcounter{secnumdepth}{3}

\setlength\LTleft{0pt}




¿Alguna vez has perdido horas configurando tu terminal o editor tras
cambiar de computadora? Los \textbf{dotfiles}, esos archivos ocultos
como \texttt{.bashrc} o \texttt{.gitconfig}, guardan tus
personalizaciones, pero gestionarlos a mano es un caos. \textbf{GNU
Stow} simplifica todo: organiza tus configuraciones en un repositorio
central y usa \textbf{enlaces simbólicos} para sincronizarlas en
minutos.

\textbf{¿Qué es Dotfiles?}

Los \textbf{dotfiles} son archivos ocultos en sistemas Unix (Linux,
macOS) que empiezan con un punto (ej., \texttt{.zshrc},
\texttt{.gitconfig}, \texttt{.config/nvim}). Almacenan configuraciones
personalizadas para tu terminal, editor de código o gestor de ventanas.
Por ejemplo, \texttt{.bashrc} define alias y variables de entorno,
mientras que \texttt{.vimrc} ajusta tu editor Vim. Estos archivos son el
corazón de tu flujo de trabajo, ya que personalizan tus herramientas
favoritas.

Tener \textbf{dotfiles} bien organizados te ahorra horas al replicar tu
entorno en nuevas máquinas. Imagina configurar tu shell o editor desde
cero tras reinstalar tu sistema: ¡es tedioso! Con una gestión adecuada,
puedes clonar tus configuraciones y tener todo listo rápidamente. Esto
es importante para desarrolladores que trabajan en múltiples
dispositivos o entornos como servidores y laptops.

\textbf{Problemas de la Gestión Manual}

Copiar \textbf{dotfiles} manualmente o usar scripts caseros es lento y
arriesgado. Puedes sobrescribir archivos, olvidar configuraciones o
perderlas en una reinstalación. Por ejemplo, mover \texttt{.zshrc} a
otra máquina sin un sistema organizado puede causar errores si las
versiones del software difieren. \textbf{GNU Stow} soluciona esto al
centralizar tus archivos y crear \textbf{enlaces simbólicos}
automáticamente, manteniendo todo sincronizado.

\textbf{¿Qué es GNU Stow?}

GNU Stow es un \textbf{gestor de granjas de enlaces simbólicos} (symlink
farm manager) que permite administrar múltiples paquetes de software o
conjuntos de archivos de configuración de manera organizada. Concepto
principal:

\begin{verbatim}
Instalar cada paquete en su propio árbol de directorios
     ↓
Usar enlaces simbólicos para que aparezcan en un árbol común
     ↓
Administrar fácilmente cada paquete de forma independiente
\end{verbatim}

\textbf{Problema original:}

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# En /usr/local/man/man1 tenías:}
\ExtensionTok{a2p.1}      \CommentTok{\# ¿De qué paquete es?}
\ExtensionTok{perl.1}     \CommentTok{\# ¿Perl?}
\ExtensionTok{emacs.1}    \CommentTok{\# ¿Emacs?}
\ExtensionTok{etags.1}    \CommentTok{\# ¿Emacs también?}

\CommentTok{\# Al desinstalar Perl... ¿qué archivos eliminar?}
\end{Highlighting}
\end{Shaded}

\textbf{Solución con Stow:}

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Cada paquete en su propio árbol:}
\ExtensionTok{/usr/local/stow/perl/}
\ExtensionTok{├──}\NormalTok{ bin/}
\ExtensionTok{│}\NormalTok{   ├── perl}
\ExtensionTok{│}\NormalTok{   └── a2p}
\ExtensionTok{└──}\NormalTok{ man/}
    \ExtensionTok{└──}\NormalTok{ man1/}
        \ExtensionTok{├──}\NormalTok{ perl.1}
        \ExtensionTok{└──}\NormalTok{ a2p.1}

\ExtensionTok{/usr/local/stow/emacs/}
\ExtensionTok{├──}\NormalTok{ bin/}
\ExtensionTok{│}\NormalTok{   └── emacs}
\ExtensionTok{└──}\NormalTok{ man/}
    \ExtensionTok{└──}\NormalTok{ man1/}
        \ExtensionTok{└──}\NormalTok{ emacs.1}

\CommentTok{\# Stow crea symlinks en /usr/local/ que apuntan a los paquetes}
\end{Highlighting}
\end{Shaded}

\textbf{Gestión de Dotfiles}

Aunque Stow fue diseñado para software, hoy en día su uso principal es
\textbf{gestionar dotfiles}:

\textbf{Ventajas:}

\begin{itemize}
\tightlist
\item
  Mantener dotfiles organizados por aplicación
\item
  Sincronizar con Git
\item
  Instalar/desinstalar configuraciones selectivamente
\item
  Mantener backups sin perder estructura
\item
  Compartir configuraciones entre máquinas
\item
  Control de versiones granular
\end{itemize}

\section{Conceptos Fundamentales}\label{conceptos-fundamentales}

\subsection{Terminología Clave}\label{terminologuxeda-clave}

\subsection{1. Package (Paquete)}\label{package-paquete}

Una colección relacionada de archivos y directorios que administras como
una unidad.

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Ejemplo: paquete "nvim"}
\ExtensionTok{nvim/}
\ExtensionTok{├──}\NormalTok{ .config/}
\ExtensionTok{│}\NormalTok{   └── nvim/}
\ExtensionTok{│}\NormalTok{       ├── init.lua}
\ExtensionTok{│}\NormalTok{       └── lua/}
\ExtensionTok{└──}\NormalTok{ .local/}
    \ExtensionTok{└──}\NormalTok{ share/}
        \ExtensionTok{└──}\NormalTok{ nvim/}
\end{Highlighting}
\end{Shaded}

\subsection{2. Target Directory (Directorio
Objetivo)}\label{target-directory-directorio-objetivo}

El directorio raíz donde quieres que aparezcan instalados tus paquetes.

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Para dotfiles, usualmente es:}
\ExtensionTok{Target:}\NormalTok{ \textasciitilde{}/ }\ErrorTok{(}\ExtensionTok{tu}\NormalTok{ HOME}\KeywordTok{)}

\CommentTok{\# Para software del sistema:}
\ExtensionTok{Target:}\NormalTok{ /usr/local}
\end{Highlighting}
\end{Shaded}

\subsection{3. Stow Directory (Directorio
Stow)}\label{stow-directory-directorio-stow}

El directorio raíz que contiene todos tus paquetes en subdirectorios
separados.

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Para dotfiles:}
\ExtensionTok{Stow}\NormalTok{ dir: \textasciitilde{}/dotfiles/}

\CommentTok{\# Para software:}
\ExtensionTok{Stow}\NormalTok{ dir: /usr/local/stow/}
\end{Highlighting}
\end{Shaded}

\subsection{4. Installation Image (Imagen de
Instalación)}\label{installation-image-imagen-de-instalaciuxf3n}

La estructura de archivos y directorios requerida por un paquete,
relativa al target directory.

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# El paquete "zsh" tiene esta imagen:}
\ExtensionTok{zsh/}
\ExtensionTok{├──}\NormalTok{ .zshrc          }\CommentTok{\# → \textasciitilde{}/.zshrc}
\ExtensionTok{├──}\NormalTok{ .zshenv         }\CommentTok{\# → \textasciitilde{}/.zshenv}
\ExtensionTok{└──}\NormalTok{ .config/}
    \ExtensionTok{└──}\NormalTok{ zsh/        }\CommentTok{\# → \textasciitilde{}/.config/zsh/}
        \ExtensionTok{└──}\NormalTok{ aliases.zsh}
\end{Highlighting}
\end{Shaded}

\subsection{5. Symlink (Enlace
Simbólico)}\label{symlink-enlace-simbuxf3lico}

Un archivo especial que apunta a otro archivo o directorio.

\begin{Shaded}
\begin{Highlighting}[]
\CommentTok{\# Ejemplo:}
\ExtensionTok{\textasciitilde{}/.zshrc} \AttributeTok{{-}}\OperatorTok{\textgreater{}}\NormalTok{ \textasciitilde{}/dotfiles/zsh/.zshrc}
         \ExtensionTok{↑}
      \ExtensionTok{symlink}
\end{Highlighting}
\end{Shaded}

\textbf{Tipos de symlinks:}

\begin{itemize}
\tightlist
\item
  \textbf{Absoluto:} \texttt{/home/user/dotfiles/zsh/.zshrc}
\item
  \textbf{Relativo:} \texttt{../dotfiles/zsh/.zshrc}
\end{itemize}

\begin{quote}
\textbf{Nota:} Stow solo crea symlinks \textbf{relativos} dentro del
target directory.
\end{quote}

\subsection{Jerarquía de Directorios}\label{jerarquuxeda-de-directorios}

\begin{verbatim}
┌─────────────────────────────────────────┐
│  /home/user/  (target directory)       │
│                                         │
│  .zshrc  ──────┐                        │
│  .config/      │                        │
│    ├── nvim/   │  symlinks             │
│    └── kitty/  │                        │
└─────────────────┼──────────────────────┘
                  │
                  ↓
┌─────────────────────────────────────────┐
│  /home/user/dotfiles/  (stow dir)      │
│                                         │
│  ├── zsh/     (package)                 │
│  │   └── .zshrc                         │
│  ├── nvim/    (package)                 │
│  │   └── .config/                       │
│  │       └── nvim/                      │
│  └── kitty/   (package)                 │
│      └── .config/                       │
│          └── kitty/                     │

\section{Conclusión}\label{conclusiuxf3n}

\subsection{Resumen de Stow}\label{resumen-de-stow}

\textbf{Ventajas:}

\begin{itemize}
\tightlist
\item
  Simple y directo
\item
  Solo hace una cosa: symlinks
\item
  Organización clara por paquetes
\item
  No modifica archivos originales
\item
  Fácil de entender y debuggear
\item
  Perfecto para dotfiles
\end{itemize}

\textbf{Desventajas:}

\begin{itemize}
\tightlist
\item
  Sin templates
\item
  Sin manejo de secrets
\item
  Requiere estructura específica
\item
  Puede ser confuso al principio
\end{itemize}
